# Поиск по фотографии

## Сейчас: демо-режим
`lib/photo-search/demo.ts` сравнивает загруженный кадр с фото каталога по цвету (гистограмма) и композиции (сетка 6×6).
Это **не** распознавание формы светильника, и на сайте режим так и подписан. Подписи (`data/signatures.json`)
грузятся отдельным чанком только при первом поиске. Товары без подписи попадают в конец списка.
Подходит только для небольшого демо-каталога.

## Полноценный поиск: что нужно
1. Сервис эмбеддингов изображений (например, CLIP/SigLIP) — свой GPU-сервер или облачный API.
2. Векторный индекс (pgvector, Qdrant, Milvus…) с записями `{ slug, imageUrl, embedding }` для каждого фото товара.
3. Индексация: при добавлении/изменении товара парсером — расчёт эмбеддинга и запись в индекс (фоновая задача).
4. HTTP-эндпоинт сервиса: `POST multipart/form-data { photo, limit }` → `{ results: [{ slug, score }] }`.
5. Переменные: `VISUAL_SEARCH_API_URL`, `VISUAL_SEARCH_API_TOKEN`, `NEXT_PUBLIC_VISUAL_SEARCH=api`.

Маршрут `app/api/visual-search/route.ts` уже проверяет файл (тип, ≤ 15 МБ) и проксирует его в сервис;
без настроек отвечает 501, клиент остаётся в демо-режиме. Подписи и изображения каталога в браузер не загружаются.
